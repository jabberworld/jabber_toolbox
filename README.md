# Jabber Toolbox

XMPP-компонент (transport), который агрегирует несколько ботов-сервисов в одном
домене компонента. Каждый бот — отдельная JID-сущность вида `NAME@<домен-компонента>`.
Пользователи Jabber добавляют ботов в ростер и общаются с ними как с обычными
контактами: пишут личное сообщение и получают ответ.

Проект написан на Python 3 + `slixmpp` (режим `ComponentXMPP`) и не требует
отдельного сервера — подключается к уже работающему XMPP-серверу как компонент.

Подробное описание архитектуры — в [AGENTS.md](AGENTS.md), полная спецификация —
в [SPEC.md](SPEC.md).

---

## Возможности

| JID-бот | Что умеет |
|---------|-----------|
| `isdown` | Проверка «сайт лежит?» по хосту, IP или URL (HTTP/HTTPS). |
| `ping` | ICMP-ping до хоста или IP (опции `-4`/`-6`). |
| `port` | Проверка доступности порта TCP/UDP (`-6`, `-u`). |
| `sslcheck` | Проверка SSL-сертификата (валидность, срок, issuer, шифры, предупреждения). |
| `shorty` | Сокращение ссылок (движки `u.to`, `clck.ru`, `is.gd`, выбор через `conf`). |
| `whois` | WHOIS по доменам и IP (с реферальными переходами и кэшем 24 ч). |
| `whoip` | Домен → IP → WHOIS (с кэшем 24 ч). |
| `note` | Личные заметки: сохранение, список, поиск, срок хранения. |
| `reminder` | Напоминания: дата/время или относительное время, архив, поиск, фоновая доставка. |

Общие возможности транспорта:

- Service Discovery (disco) для компонента и каждого бота;
- ad-hoc-команда для добавления бота в ростер;
- автоматический обмен подписками и зеркалирование присутствия пользователя
  на его ботов (боты «появляются»/«исчезают» вместе с пользователем);
- ответы на version, uptime, vCard и время;
- подтверждения доставки (XEP-0184) и индикация набора (XEP-0085);
- регистрация «в band» (XEP-0077) для самого транспорта.

## Системные требования

- **Python 3.8+** (используются asyncio, `async/await`);
- **Linux-подобная ОС** (для бота `ping` требуется системная утилита `ping`);
- **XMPP-сервер**, поддерживающий компоненты (например, ejabberd, Prosody);
- **доступ в сеть** — для сетевых ботов (TCP/SSL/WHOIS/HTTP-API);
- файл `requirements.txt`: `slixmpp==1.10.0`.

## Процедура запуска

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Настройка конфигурации

```bash
cp config.ini.example config.ini
```

Отредактируйте `config.ini`:

```ini
[server]
JID = service2.example.com   ; домен компонента
Host = 127.0.0.1             ; адрес XMPP-сервера
Port = 5275                  ; порт компонентного соединения
Password = changeme          ; компонентный пароль

[settings]
; Смещение часового пояса от UTC в часах (например 3 для Москвы).
Timezone = 0
; Длина первой строки, используемой как автозаголовок (по умолчанию 20).
TitleDefaultLength = 20
```

### 3. Запуск

```bash
python3 toolbox.py
```

### 4. Самопроверка (без сервера)

```bash
python3 selftest.py
```

### 5. Автозапуск через systemd

В репозитории есть готовый unit-файл `toolbox.service`. Установите его на хост:

```bash
sudo install -m 0644 toolbox.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now toolbox
```

Проверка статуса и логов:

```bash
systemctl status toolbox
journalctl -u toolbox -f
```

При необходимости измените в файле `User`, `WorkingDirectory` и `ExecStart`
под ваше окружение (например, `User=jabbertoolbox` и путь до проекта).

## Краткое руководство по использованию

### Как добавить бота

1. Выполните ad-hoc-команду на узле `/component/<имя бота>` (кнопка «восклицательный
   знак» в большинстве клиентов) — бот пришлёт запрос подписки.
2. Одобрите запрос — бот станет доступен в ростере.
   Либо добавьте JID бота напрямую (например `note@домен`) и одобрите подписку.

Отправьте боту `help` (или `?`), чтобы увидеть его справку.

### isdown — «сайт лежит?»

`google.com`, `8.8.8.8:80`, `http://google.com`, `[2001:4860:4860::8888]:443`.
Порт по умолчанию — 443 (для `http://` — 80).

### ping

`ping linuxoid.in` — 4 пакета; `ping -4 <host>` / `ping -6 <host>`.

### port

`example.com 443`, `-6 example.com 25`, `-u 8.8.8.8 53` (UDP).

### sslcheck

`google.com`, `example.com:8443`, `https://example.com`. Проверяет совпадение
имени хоста, срок действия, издателя, протокол/шифры и наличие предупреждений.

### shorty — сокращение ссылок

Отправьте ссылку (URL или домен), например `https://example.com/very/long/link`.
`conf` — вывести список движков и выбрать (по умолчанию `u.to`).

### whois / whoip

`whois` — `linuxoid.in` или IP. `whoip` — домен сначала резолвится в IP, затем
выполняется WHOIS (например `google.com`). Результаты кэшируются на 24 часа.

### note — личные заметки

- Отправьте любой текст — сохранится как заметка с автозаголовком.
- `list` — список заметок (новые сверху), `srch <текст>` — поиск по заголовку и
  содержимому (регистр не важен).
- Номер заметки — открыть её.
- Внутри открытой заметки: `1|title` — заголовок, `2|add` — добавить текст,
  `3|del` — удалить, `4|old` — срок хранения, `0` — выход.
- По умолчанию заметка хранится бессрочно.

### reminder — напоминания

- Отправьте любой текст — создастся напоминание «через 1 час» и откроется пикер
  даты/времени. Настройте поля (1–5), выберите `6` для относительного времени
  («через N минут/часов/...»), затем `7. Сохранить`.
- `list` — активные напоминания, `arch` — доставленные, `srch <текст>` — поиск.
- Номер — открыть напоминание.
- Внутри: `1|title`, `2|body`, `3|del`, `4|remind` (время), `5|old` (срок хранения),
  `0` — выход.
- При наступлении времени бот сам пришлёт «Напоминание: <заголовок>».
- По умолчанию напоминание хранится 7 дней.
